## Overview

b_platform 是独立部署的**业务基础平台（控制面）**，被多个业务系统共同依赖。它负责租户与
数据隔离、身份与认证、租户内组织目录与成员关系、三层权限、审计、平台配置、扩展模块注册、
服务账号与事件出口；不承载任何行业业务域。

本规格是 V2.0 设计基线的业务层收敛，作为后续技术规划与任务拆解的输入；接口字段与错误语义
以设计基线中的 API 契约为唯一权威。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 平台开通租户并交付给租户所有者 (Priority: P1)

平台运营方创建一个租户，指定名称、标识与初始所有者；系统在同一事务内建立初始所有者成员
关系与所有者角色，租户立即可用。租户可被冻结、解冻、关闭，关闭不删除数据。

**Why this priority**: 没有租户就没有隔离边界，其他所有能力都无处落地。

**Independent Test**: 仅实现租户生命周期即可验证——创建租户后初始所有者能以该租户上下文
登录并读取本租户信息；冻结后写操作被拒绝；关闭后禁止登录。

**Acceptance Scenarios**:

1. **Given** 平台运营方已登录，**When** 创建租户并指定初始所有者，**Then** 租户状态为可用，
   且该用户立即拥有租户所有者角色。
2. **Given** 租户处于可用状态，**When** 平台冻结该租户，**Then** 该租户下所有业务写操作被
   拒绝，平台仍可解冻或经审计的强制管理。
3. **Given** 租户已关闭，**When** 该租户成员尝试登录，**Then** 登录被拒绝且数据仍然保留。

---

### User Story 2 - 用户注册、登录与上下文切换 (Priority: P1)

用户以邮箱/手机号注册并完成联系方式验证，使用账号密码登录；可在自己有有效成员关系的
租户/组织之间切换上下文；可查看并撤销自己的会话；忘记密码时可重置并失效既有会话。

**Why this priority**: 身份是所有授权判定的输入，且是平台唯一直接面向最终用户的能力。

**Independent Test**: 仅实现身份域即可验证——注册→验证→登录→刷新→切换上下文→登出闭环
可用；重置密码后旧会话失效。

**Acceptance Scenarios**:

1. **Given** 用户已注册但未验证联系方式，**When** 尝试登录，**Then** 按策略要求先完成验证。
2. **Given** 用户属于两个租户，**When** 切换上下文，**Then** 重新签发携带目标租户/组织的
   上下文凭证。
3. **Given** 用户连续登录失败达到阈值，**When** 再次尝试，**Then** 账号被临时锁定并给出剩余时间。
4. **Given** 用户重置密码成功，**When** 使用旧会话凭证访问，**Then** 请求被拒绝。

---

### User Story 3 - 租户内组织、成员与三层授权 (Priority: P2)

租户管理员在租户内创建组织（可配置审批）、维护组织树（父子同租户、深度受限）、邀请与
移除成员、创建自定义角色并分配；组织所有者可发起所有权转让；平台可按范围授予平台角色。
授予的任何权限集合必须是被授予者之外的操作者权限子集。

**Why this priority**: 这是业务系统实际使用的核心能力，但依赖租户与身份先就绪。

**Independent Test**: 仅实现组织/成员/角色即可验证——建树→邀请成员→分配角色→成员按角色
访问被授权的组织；越权授予与所有者改派被拒绝。

**Acceptance Scenarios**:

1. **Given** 组织创建需要审批，**When** 成员提交创建申请，**Then** 审批通过后创建者成为组织
   所有者，未通过则不创建组织。
2. **Given** 目标父组织属于其他租户，**When** 创建子组织，**Then** 请求被拒绝。
3. **Given** 操作者只有 `tenant.member.read`，**When** 尝试分配包含更高权限的角色，**Then**
   请求被拒绝并记录拒绝审计。
4. **Given** 成员被移除或角色被停用，**When** 其使用旧凭证访问，**Then** 下一次请求即失效。
5. **Given** 组织所有者发起转让，**When** 目标不是有效组织成员，**Then** 转让被拒绝。

---

### User Story 4 - 审计可查、可导出、不可篡改 (Priority: P2)

租户审计员查看本租户审计，平台审计员查看全平台审计；查询行为本身被审计；审计可按时间
归档并导出。审计记录不可更新、不可删除。

**Why this priority**: 合规与追责依赖审计，且审计必须与业务同事务才能可信。

**Independent Test**: 仅实现审计域即可验证——关键操作产生审计记录；应用角色无法更新/删除
审计；导出任务产生导出审计并返回可下载结果。

**Acceptance Scenarios**:

1. **Given** 业务事务成功提交，**When** 查询审计，**Then** 存在对应动作记录且含操作者、目标、结果。
2. **Given** 审计写入失败，**When** 业务事务提交，**Then** 整个事务回滚，业务失败。
3. **Given** 租户审计员，**When** 查询其他租户审计，**Then** 返回空结果或拒绝。
4. **Given** 审计查询请求，**When** 查询完成，**Then** 产生一条审计查询记录。

---

### User Story 5 - 扩展模块按 SPI 接入与启停 (Priority: P3)

扩展模块以 Manifest 注册名称、版本、API 版本、权限、路由、迁移、事件、配置 schema 与 UI
扩展点；平台可启用/禁用扩展，禁用不删除数据且路由不挂载；扩展使用独立 schema，不得访问
核心表。

**Why this priority**: 平台价值来自可扩展性，但一期可先交付核心能力。

**Independent Test**: 仅实现扩展注册表即可验证——注册一个示例扩展→启用后其路由可达、权限
进入权限表→禁用后路由不可达、数据保留。

**Acceptance Scenarios**:

1. **Given** 扩展 Manifest 声明 `platform.*` 权限，**When** 注册，**Then** 启动失败并报告原因。
2. **Given** 扩展已启用，**When** 平台禁用该扩展，**Then** 其路由不再挂载且数据保留。
3. **Given** 扩展迁移试图修改核心表，**When** 执行迁移，**Then** 迁移被拒绝。

---

### User Story 6 - 服务账号、API Key 与事件出口 (Priority: P3)

平台/租户可创建服务账号并以 Client Credentials 或 API Key 调用授权范围内的接口；关键领域
事件与业务同事务写入事件出口，由 Worker 异步投递到租户配置的 Webhook（HMAC 签名、重试、
死信、告警）。

**Why this priority**: 与其他系统集成时需要，但可在核心闭环后交付。

**Independent Test**: 仅实现服务账号与事件出口即可验证——服务账号取到受限凭证并成功调用
授权接口；业务事件被投递到 Webhook 且签名可验证；失败按策略重试并进入死信。

**Acceptance Scenarios**:

1. **Given** 服务账号只有租户读权限，**When** 调用租户写接口，**Then** 返回权限拒绝。
2. **Given** API Key 已撤销，**When** 使用该 Key 调用，**Then** 返回统一无效凭证错误。
3. **Given** Webhook 端点持续返回 5xx，**When** 超过重试次数，**Then** 消息进入死信并触发告警。

### Edge Cases

- 同一用户在同一租户存在多条历史成员记录：只有有效记录参与授权，历史记录保留可查。
- 租户冻结期间平台强制管理：允许经审计的强制读写，但必须记录跨租户访问审计。
- 组织树达到深度上限：创建子组织被拒绝，返回明确错误而非静默截断。
- 祖先组织被冻结且开启级联：后代组织的写操作被拒绝。
- 重复提交同一写请求（同一幂等键、同请求体）：返回首次响应；同键不同请求体返回冲突。
- 一次性令牌被消费或撤销后再次使用：拒绝，且撤销与消费通过审计动作区分。
- 扩展被禁用后其权限点仍存在于角色中：权限判定忽略未启用扩展的权限点。
- 审计导出链接过期：拒绝下载并记录拒绝审计。

## Requirements *(mandatory)*

### Functional Requirements

编号沿用设计基线的 `FR-*` 标识以保持与 `docs/10-requirements/requirements-v2.0.md` 及追溯矩阵
的双向可追溯；共 61 条。

**租户（FR-T）**

- **FR-T-01**: 平台运营方 MUST 能创建租户并指定名称、标识与初始所有者，且在创建时同事务建立
  所有者成员关系与角色。
- **FR-T-02**: 平台运营方 MUST 能查询租户列表与详情；租户成员 MUST 能查看自己所属租户。
- **FR-T-03**: 租户管理员 MUST 能更新租户名称与配置；租户标识 MUST NOT 可修改。
- **FR-T-04**: 平台运营方 MUST 能冻结/解冻租户；冻结期间 MUST 拒绝该租户全部业务写操作。
- **FR-T-05**: 租户关闭 MUST 只置状态并保留数据；关闭后 MUST 禁止登录与写入。
- **FR-T-06**: 任一租户成员 MUST NOT 能通过接口、错误标识、关联查询或伪造上下文访问其他租户数据。

**身份与认证（FR-I）**

- **FR-I-01**: 系统 MUST 支持邮箱/手机号注册，注册后 MUST 完成联系方式验证；账号全局唯一。
- **FR-I-02**: 系统 MUST 支持账号密码登录并签发访问凭证与刷新凭证；平台入口与普通用户入口
  MUST 使用不同受众。
- **FR-I-03**: 刷新凭证 MUST 轮换并检测重用；密码重置或账号禁用后 MUST 失效。
- **FR-I-04**: 用户登出 MUST 使当前刷新凭证失效。
- **FR-I-05**: 系统 MUST 支持忘记密码、一次性重置令牌；重置后 MUST 使既有会话失效。
- **FR-I-06**: 联系方式验证令牌 MUST 一次性且有时效。
- **FR-I-07**: 系统 MUST 在连续失败达阈值后临时锁定账号，并 MUST 支持按账号/来源限流。
- **FR-I-08**: 平台运营方 MUST 能禁用/启用用户；禁用 MUST 使全部会话失效；启用 MUST NOT 自动
  恢复成员关系。
- **FR-I-09**: 用户 MUST 能查看/撤销自己的会话；平台管理员 MUST 能撤销指定用户会话。
- **FR-I-10**: 用户 MUST 能在有有效成员关系的租户/组织间切换，并在切换后重新签发上下文凭证。
- **FR-I-11**: 服务账号 MUST 支持 Client Credentials 与 API Key；API Key MUST 只存哈希且可过期/撤销。

**组织（FR-O）**

- **FR-O-01**: 有权限的租户成员 MUST 能创建组织，且组织 MUST 属于当前租户。
- **FR-O-02**: 组织创建 MUST 可配置为需要租户内审批；通过后创建者 MUST 成为组织所有者。
- **FR-O-03**: 组织 MUST 支持父子层级；父子 MUST 同租户；深度 MUST 受参数限制。
- **FR-O-04**: 租户成员 MUST 能按权限查看组织及其下级，且 MUST NOT 跨租户。
- **FR-O-05**: 组织管理员 MUST 能更新组织名称、配置与可见性策略。
- **FR-O-06**: 租户管理员或平台运营方 MUST 能冻结/解冻组织；冻结期间 MUST 拒绝该组织写操作；
  祖先冻结级联 MUST 可配置。
- **FR-O-07**: 组织所有者 MUST 能发起转让；目标 MUST 是有效组织成员；平台 MUST 能强制转让并审计。
- **FR-O-08**: 一期 MUST NOT 支持组织物理删除与父组织变更，接口 MUST 明确拒绝。

**成员与角色（FR-M）**

- **FR-M-01**: 租户管理员 MUST 能邀请/移除租户成员；成员 MUST 可拥有多个租户角色。
- **FR-M-02**: 组织管理员 MUST 能邀请/移除组织成员；组织成员 MUST 同时是租户成员。
- **FR-M-03**: 成员状态 MUST 包含 `INVITED`/`ACTIVE`/`SUSPENDED`/`INACTIVE`；移除 MUST 保留历史。
- **FR-M-04**: 租户/组织 MUST 能创建自定义角色，且角色权限集合 MUST 是操作者权限集合的子集。
- **FR-M-05**: 成员 MUST 可拥有多个角色；角色停用/移除后 MUST 在下一请求即时失效。
- **FR-M-06**: 授予/修改角色时目标权限集合 MUST ⊆ 操作者权限集合。
- **FR-M-07**: 租户/组织所有者角色 MUST 受硬保护，只能通过专用转让流程变更；任一时刻 MUST
  只有一个所有者。
- **FR-M-08**: 平台角色 MUST 支持 `ALL`/`TENANT`/`ORGANIZATION`/`ORG_TYPE` 授权范围，多范围
  MUST 取并集，默认 MUST NOT 含下级且可选含后代。
- **FR-M-09**: 成员移除、角色变更、用户禁用 MUST 递增权限版本，旧凭证与缓存 MUST 失效。

**权限点（FR-P）**

- **FR-P-01**: 核心权限点 MUST 由平台维护；扩展权限点 MUST 由 Manifest 以 `ext.<module>.*`
  命名空间注册。
- **FR-P-02**: 权限点作用域 MUST 为 `PLATFORM`/`TENANT`/`ORGANIZATION`。
- **FR-P-03**: 权限点编码发布后 MUST NOT 修改，只能废弃后新增。
- **FR-P-04**: 所有授权判定 MUST 走统一授权组件，Handler/Service MUST NOT 硬编码角色判断。
- **FR-P-05**: 扩展 MUST 只能注册 `TENANT`/`ORGANIZATION` 作用域权限。

**审计（FR-A）**

- **FR-A-01**: 审计 MUST 覆盖登录、注册、密码重置、用户禁用、租户创建/冻结、组织创建/审批/冻结、
  成员邀请/移除、角色变更、所有者转让、平台角色授予、服务账号/API Key 变更、扩展启停、跨租户访问。
- **FR-A-02**: 关键安全事件 MUST 与业务事务同事务写入；审计失败 MUST 使业务失败并回滚。
- **FR-A-03**: 审计记录 MUST NOT 被更新或删除；应用角色 MUST 只持有插入权限。
- **FR-A-04**: 租户审计员 MUST 能查看本租户审计，平台审计员 MUST 能查看全平台审计；审计查询
  本身 MUST 被审计。
- **FR-A-05**: 审计 MUST 支持按时间归档与导出，保留周期 MUST 可配置。

**平台配置（FR-C）**

- **FR-C-01**: 平台运营方 MUST 能管理平台参数（登录失败阈值、凭证有效期、组织树深度上限、
  是否允许组织审批等）。
- **FR-C-02**: 租户管理员 MUST 能管理租户级配置，配置 MUST 按 schema 校验且变更 MUST 审计。
- **FR-C-03**: 平台参数 MUST 区分公开/平台私有；租户 MUST 只能读取公开参数。

**扩展（FR-E）**

- **FR-E-01**: 扩展 MUST 通过 Manifest 注册名称、版本、API 版本、权限、路由、迁移、事件、
  配置 schema 与 UI 扩展点。
- **FR-E-02**: 平台运营方 MUST 能启用/禁用扩展；禁用 MUST NOT 删除数据且 MUST 不挂载路由。
- **FR-E-03**: 扩展 MUST 使用独立 schema，MUST NOT 修改或直接访问核心表。
- **FR-E-04**: 扩展权限 MUST 注册到权限表并可被各级角色授予。
- **FR-E-05**: 扩展升级 MUST 兼容当前 API 版本，迁移 MUST 独立管理。

**服务账号（FR-S）**

- **FR-S-01**: 平台运营方/租户管理员 MUST 能创建服务账号并指定名称、作用域与有效期。
- **FR-S-02**: 服务账号 MUST 能通过 Client Credentials 获取携带受众与作用域的凭证。
- **FR-S-03**: 服务账号 MUST 能创建 API Key；Key MUST 只存哈希、只显示一次、可过期/撤销。
- **FR-S-04**: 服务账号创建、密钥轮换、撤销与使用异常 MUST 被审计。

**事件与集成（FR-X）**

- **FR-X-01**: 关键领域事件 MUST 与业务同事务写入事件出口，由 Worker 异步投递。
- **FR-X-02**: 租户 MUST 能配置 Webhook 端点；投递 MUST 带签名、支持重试、死信与延迟告警。
- **FR-X-03**: 平台 MUST 对外提供签名公钥端点，供其他系统本地校验凭证。
- **FR-X-04**: 核心 API MUST 提供机器可读契约，扩展 API MUST 合并到同一契约。
- **FR-X-05**: 核心与扩展、核心与消费方之间 MUST 建立契约测试。

### Key Entities *(include if feature involves data)*

- **Platform User**：平台注册用户，账号全局唯一，含状态、凭证哈希与权限版本；不参与租户隔离。
- **Tenant**：数据隔离边界，含标识、名称、状态、配置与所有者；标识不可变。
- **Tenant Membership**：用户与租户的关系，含状态与权限版本；同一用户同一租户有效记录唯一。
- **Organization**：租户内业务组织，含父组织、类型、名称、状态、所有者；父子必须同租户。
- **Organization Closure**：组织树的祖先-后代关系与深度，用于子树查询。
- **Organization Membership**：用户与组织的关系；必须是该租户成员。
- **Role / Permission / Role Permission**：三层作用域下的角色与权限点集合；所有者角色唯一。
- **Platform Role Grant / Grant Scope**：平台角色授予及其范围（全部/租户/组织/组织类型）。
- **Audit Log**：只追加的审计记录，含操作者、目标、动作、结果、来源与快照。
- **Service Account / API Key**：机器身份与只存哈希的调用凭证。
- **Extension Registry**：扩展名称、版本、API 版本、状态与 Manifest。
- **Outbox Event**：与业务同事务写入的领域事件及其投递状态。
- **Idempotency Key**：主体+端点+键+请求哈希+响应快照，用于重放保护。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新租户从创建到初始所有者可正常使用，全流程在 2 分钟内完成且无需人工修数据。
- **SC-002**: 100% 的租户数据访问请求经过隔离校验；跨租户读取尝试成功率为 0（隔离测试集全过）。
- **SC-003**: 关键安全操作 100% 产生审计记录，且审计写入失败时业务成功率降为 0（事务强一致）。
- **SC-004**: 61 条功能需求 100% 可在契约、权限点、审计动作、事件与测试锚点中定位到落点。
- **SC-005**: 认证与授权判定在正常负载下 95% 的请求在 50 毫秒内完成（不含网络）。
- **SC-006**: 单租户万级组织规模下，组织树查询 95% 在 300 毫秒内返回。
- **SC-007**: 平台可承载 10,000 个租户与 1,000,000 个用户而不降低上述指标。
- **SC-008**: 越权授予与所有者改派尝试 100% 被拒绝并留痕。
- **SC-009**: 事件投递在消费者可用时 99% 在 1 分钟内送达；失败投递 100% 进入死信并告警。
- **SC-010**: 扩展启用/禁用可在不重启核心、不丢失数据的前提下完成。

## Assumptions

- 一期采用共享数据库 + 行级隔离；schema-per-tenant/database-per-tenant 属于后续演进，不在本期。
- 一期不提供组织物理删除、父组织变更与租户物理删除，相关接口明确拒绝。
- 组织审批为可配置能力，默认关闭。
- 多因素认证与高危操作二次验证属二期；一期仅保留审计增强语义。
- 上下文切换属已认证读取行为，一期不写审计，由日志与指标承载。
- 邮件/短信/推送渠道由外部系统实现，平台只定义接口与事件。
- 消费方（Bufaa/Tufaa/MuPlan）通过公开契约与签名公钥自行校验凭证，不共享数据库。
- 行业组织类型字典由扩展或配置提供，核心只定义扩展点。
